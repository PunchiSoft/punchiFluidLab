# Event sounds

Four samples, all generated by this repository. Nothing here is a recording taken from
another program, a sound bank or a website, so there is no licence to track beyond the
project's own: **GPL-3.0-or-later**, the same terms as the rest of the tree.

| File | Plays when | Length | Rate |
|---|---|---|---|
| `valve.wav` | the valve's spool actually changes position | 0.45 s | 44 100 Hz mono |
| `air.wav` | the transport starts | 5 s | 44 100 Hz mono |
| `cylinder.wav` | **the piston reaches an end of its stroke, moving** | 0.40 s | 44 100 Hz mono |
| `buzzer.wav` | **an audible indicator is live**, looped until it stops | 1 s | 44 100 Hz mono |

The reference separates its sounds the same way (§4.13 of its manual): `switch.wav` for
switches and relays, `valve.wav` for valves, `horn.wav` for the horn, and `cylinder.wav`
for **the cylinder's end positions**. The last is the sound a pneumatic circuit actually
makes, so it is the loudest event here and the valve is only a short tick. `buzzer.wav` is
the one sound that lasts: it loops while the indicator's line is live (ADR 0022).

## Where the sound comes from

`scripts-dev/make-sounds.py` synthesises all four from filtered noise and a fixed seed, so
the committed bytes are reproducible: running the script again rewrites the same files.

```bash
./scripts-dev/make-sounds.py
```

- **`valve.wav`** is one syllable: a 6 ms transient for the spool, then band-limited
  noise (900–6500 Hz) decaying over 85 ms for the exhaust behind it.
- **`air.wav`** is the bed of a volume being charged: band-limited noise (260–8000 Hz),
  slowly modulated so it breathes instead of humming, and falling away as the volume
  approaches the supply — the shape the model itself has.
- **`cylinder.wav`** is a stop in three parts: a hard clack of metal on metal
  (1600–11 000 Hz, 8 ms), a low thud of the barrel taking the blow (96 Hz and 210 Hz,
  decaying over 55 ms) and a short tail of air behind the piston. The clack is the event;
  the rest is the room.
- **`buzzer.wav`** is a tone with its odd harmonics and a slow pulse: 440 Hz, 1 s, an integer
  number of cycles and no fade, so the loop joins without a click. It is generated, not
  recorded, like the rest.

Only a *moving* arrival sounds. A piston that creeps up to the stop has nothing to
report, and the model can rebound a few millimetres off the stop before the chamber
charges — several arrivals within 50 ms are collapsed into one hit, because that is what
a listener hears. `punchi-fluid-solver` pins the rebound with a test, so if a later change
removes it the collapse can be simplified on purpose instead of by accident.

The event samples were measured against the character of real compressed-air recordings: a spectral
centroid around 8.4 kHz, no DC offset, peak at −4 dBFS and −6 dBFS respectively. The
test that matters is not the number, it is `--check-sounds`: the shipped binary has to
load and decode them, or it exits non-zero. `--check-sounds` includes the buzzer.

## Replacing them

A file with the same name in `$XDG_DATA_HOME/punchi-fluid-lab/sounds/` — normally
`~/.local/share/punchi-fluid-lab/sounds/` — is used instead of the built-in copy:

```bash
mkdir -p ~/.local/share/punchi-fluid-lab/sounds
cp valve.wav air.wav cylinder.wav buzzer.wav ~/.local/share/punchi-fluid-lab/sounds/
```

The rule is the catalog's: the user's material wins, the built-in copy is the floor. A
recording made in a real workshop will always beat a synthesised one, and trying it must
not need a rebuild. The format must be **WAV** — `QSoundEffect` reports `Error` for
anything else, including MP3, and a renamed file is caught by `--check-sounds` before it
becomes silence in the mixer. Convert with:

```bash
ffmpeg -i recording.mp3 -ac 1 -ar 44100 -c:a pcm_s16le valve.wav
```

Files in the user folder are the user's own; they are not compiled into the binary and
never enter the repository.
